A Primer to Understanding Quantization for LLMs

May 22, 2026 • 10 min read

The more and more LLMs get better, they also seem to be getting bigger. The frontier models have over 1 trillion parameters. It's also cool when all you have to do is invoke an api and generate the response. What if i wanted to host this model myself? What would i need to do. First step would be to load the weights into memory. For context, a 70B Llama in fp32 would need ~ 32/8 * 70 = 280 GB. Oh, 280GB for a 70B model? Forget about 1T models then. Just kidding. This is where quantization is super crucial. In plain terms, quantization is a technique by which i can make LLMs N times smaller and faster just sacrificing a fraction of performance. Pretty cool yes?

But before talking about how quantization works, you really need to lock in the concept of how numbers are stored in memory. We will focus mostly on the floating point formats like half(fp16), bfloat16, and int8. So this post is really about building the mental model for those formats first.

How to represent numbers

Floating point numbers are stored using three parts:

  • Sign bit: tells us whether the number is positive or negative.
  • Exponent bits: tell us the scale of the number.
  • Mantissa bits: the fractional part that usually tells how precise the number is.

The rough idea is: 

value = (-1)^sign × (1.fraction) × 2^(exponent - bias)

We will look at each of these components in detail.

float32

fp32 is the standard 32-bit floating-point format and is often the reference format people have in mind when they say "full precision."

  • we have 1 bit for sign. 0 means positive, 1 means negative.
  • 8 bits for exponent
  • 23 bits for mantissa

now, according to IEEE-754 convention, the exponents are stored in a biased form. ``` Estored = Eactual + bias where bias = 2^(k − 1) − 1 k = exponent bits ```

for fp32, bias = 2 ^ 8 - 1 = 255 So for fp16 we shift them by +255 when storing, and then subtract -255 when reading.

the exponent field cannot be all zeros or all ones. That means:

  • 00000000 is reserved for zero and subnormal values
  • 11111111 is reserved for infinity and NaNs
  • So out of the total 256 exponents, valid normalized stored exponents are from 1 to 254

So the actual exponent range for normalized fp32 values is: 

-126 ≤ E ≤ 127

fp32 gives you both a huge range and high precision, but it costs 32 bits per number. For LLMs with billions of parameters, that memory cost scales up real quick.
