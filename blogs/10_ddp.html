Everything you need to know about Pytorch Distributed Data Parallel(DDP)

May 28, 2026 • 20 min read

Distributed Data Parallel (DDP) is a pytorch module that supports multi-machine, multi-GPU, distributed training. In DDP, you run copies of the model independently on each GPU and later sync to update gradients across the different data. (write this better)

In this post we will cover everything you need to know and write some distributed training scripts for LLMs!

How to think about scaling to multiple GPUS

the scenario for training on multiple GPUs vs inference on multiple GPus is extreemly different. in this post, we only focus on the training setup. we will also turn out focus specifically on data parallelism that pytorch DDP offers although which is the simplest technique to start scaling to multiple gpus.

I have 10 zillion data samples which if i run on a single GPU is probably going to take years. what if i split the data across the N gpus i have, and then run the specific split of data across each model running on each GPU.

hmmm, that wont cut it, because if they run independently, they will end up being N different models instead of a single one. instead we need a single model that is somehow able to accumulate knowledge from all the other runnings gpus.

At this point, it good to remind ourselves of how training a model works.

Training a Model

i would probably describe the flow as follow -

1. create batches of data 2. at each time step, feed one batch through the model 3. get logits and pass through softmax for scores

4. calculate loss 5. update weights

perfect, now out of the five stages i described, what do you think is the stage that has the most impact on the models learning? the weight updation! basically, its okay to independently run all the stages of training on different gpus as long you are able to sync the gradients to make a final proper weight updation.

DDP offers to do exactly this, a smart way to sync gradients across multiple gpus and then let the training carry on.

Basic Terminology

world size The number of parallel operations worldwide is simply 2 x 8 = 16. # world size torch.distributed.get_world_size() rank This represents the sequence number of the current process, used for inter-process communication. For a world size of 16, this is 0, 1, 2, ..., 15. Note: The process with rank=0 is the master process. # rank torch.distributed.get_rank() local_rank Another sequence number. These are the process numbers on each machine. Machine 1 has 0, 1, 2, 3, 4, 5, 6, 7, and Machine 2 also has 0, 1, 2, 3, 4, 5, 6, 7. # local rank torch.distributed.local_rank()
